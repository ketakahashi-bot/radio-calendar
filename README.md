# ラジオ番組カレンダー

地上波ラジオ・ネットラジオ・YouTube・ポッドキャストに分かれた番組を、1つの深夜表記（25時表示）のカレンダーで管理する PWA です。
放送予定は Google カレンダーへ自動で登録し、通知は iPhone の Google カレンダーアプリに任せます。
投稿先・コーナー・お題・投稿履歴もまとめて管理します。

HTML / CSS / JavaScript だけで動きます。ビルドも `npm install` も不要で、費用はかかりません。
現在の版は 2.0.0（要件定義書 第2版）です。

## 使い始めるまで

1. アプリを公開する（iPhone で使うには HTTPS が必要）
2. Google 連携用の GAS を設置する
3. iPhone の Safari で開き、ホーム画面に追加して連携する

### 1. アプリを公開する（GitHub Pages の場合）

このフォルダの中身を GitHub の公開リポジトリに置き、リポジトリの **Settings > Pages** で
公開元のブランチを選びます。数分で `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。

Cloudflare Pages でも、このフォルダをそのままアップロードすれば動きます（ビルドコマンドは不要）。

### 2. GAS を設置する

GAS はあなたの Google アカウントの中で動く中継役で、データは開発者のサーバーを通りません。
操作するのは、GAS が自分で作るカレンダー「ラジオ番組」、ToDo リスト「ラジオ番組」、
ドライブのフォルダ「ラジオ番組カレンダー」だけです。

1. <https://script.google.com/> で **新しいプロジェクト** を作る
2. `gas/Code.gs` の中身を、エディタの `コード.gs` に貼り付ける
3. **プロジェクトの設定（歯車）** で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、
   エディタの `appsscript.json` を `gas/appsscript.json` の中身に置き換える
4. **デプロイ > 新しいデプロイ** で種類「ウェブアプリ」を選び、次の設定でデプロイする
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
5. 権限の確認が出たら許可する（「このアプリは Google で確認されていません」と出たら、
   詳細 > 安全ではないページに移動。自分で作ったスクリプトなので問題ありません）
6. エディタで関数 `setup` を選んで **実行** する（権限の確認が出たら許可する）

連携用URLと合言葉が自分宛てのメールで届きます（実行ログにも出ます）。
メールのURLが末尾 `/exec` でないときは、**デプロイ > デプロイを管理** に出ているウェブアプリのURLをコピーしてください。
`setup` は、1時間ごとの新着確認と毎日の世代整理の定期処理も登録します。

| 設定画面のエラー | 確認すること |
| --- | --- |
| 末尾が /dev のURLは使えません | **デプロイを管理** の `/exec` のURLに貼り替える |
| GAS に接続できません | デプロイの「アクセスできるユーザー」が **全員** か |
| 合言葉が一致しません | `setup` のメールの合言葉をコピーし直す |
| appsscript.json が反映されていません | 手順3をやり直し、新しいバージョンでデプロイし直す |
| GAS が古い版です | 下の「GAS を更新する」を行う |
| GAS の定期処理が未登録です | エディタで `setup` を実行する |

> 「全員」と設定しても、合言葉がなければデータには触れません。ただし連携用URLと合言葉は他の人に教えないでください。

### GAS を更新する（第1版から使っている場合）

第2版の新着の自動検知・今日のまとめ・合言葉の再発行は、GAS の更新が必要です。連携用URLと合言葉は変わりません。

1. GAS のエディタで `コード.gs` の中身を、新しい `gas/Code.gs` の中身にすべて置き換えて保存する
2. **デプロイ > デプロイを管理** で、いまのデプロイの鉛筆ボタンを押し、バージョンを **新バージョン** にして **デプロイ**
3. エディタで関数 `setup` を選んで **実行** し、権限の確認が出たら許可する（外部の RSS の読み込みと定期処理の権限が増えます）
4. アプリの **設定 > Google 連携 > すべて送り直す** を押す

### 3. iPhone で使う

1. Safari で公開したURLを開き、共有メニューから **ホーム画面に追加**
2. ホーム画面のアイコンから起動し、**設定 > Google 連携** に連携用URLと合言葉を貼り付けて「連携する」
3. **設定 > 通知 > 睡眠・集中モードでも鳴らす設定** の手順で Google カレンダーアプリの通知を許可し、**通知テスト** で鳴るか確かめる
4. Gmail アプリから投稿したい場合は **Gmail アプリ** も入れる

機種変更のときは、アプリの **設定 > 機種変更の手順** を見てください。前の端末の QR コードを新しい端末で読み取るだけで連携でき、ドライブのバックアップを件数つきで確認してから復元できます。

## できること

| 領域 | 内容 |
| --- | --- |
| 番組 | 登録・編集・削除、放送枠（毎週／隔週／毎月第n曜日／単発）、深夜表記（5:00〜28:59）、放送期間、アーカイブ、最終回、お気に入り、検索・絞り込み・並び替え、汎用アイコン |
| 配信媒体 | AM / FM / ワイドFM / ネット / YouTube / ポッドキャスト / その他、周波数・URL・地域、時刻のずれ、聴き逃し配信、プリセット、放送局単位の一括付け替え |
| カレンダー | 月／週／日、5:00 区切り、番組カラー、今放送中・次の放送、締切と聴取期限の印 |
| 未聴 | 未聴の放送回（期限の近い順）、新着の回、タイムフリーの残り日数・24時間と3時間の残り |
| 新着の自動検知 | YouTube チャンネル・ポッドキャストの RSS を1時間ごとに確認（アプリを閉じていても動く）、タイトルでの絞り込み、通知なしの予定登録 |
| 通知 | 放送開始（番組ごと・回ごと）、毎朝の「今日のまとめ」、個別通知への切り替え、通知テスト、集中モードの設定案内 |
| 投稿 | 締切一覧、投稿履歴（メールは自動で記録）、「読まれた」記録と radiko へのリンク、採用率、ネタ帳、番組ごとのラジオネーム、署名、Gmail 起動 |
| X | ハッシュタグ（複数）と公式アカウント、実況する、みんなの反応、X で受け付けるコーナーへの投稿（API は使わずリンクで開く） |
| 振り返り | 月ごとの聴いた回数・聴き逃した回数・投稿数・読まれた数、続けて聴いている週（端末内だけで集計） |

| Google | カレンダー自動同期、オフライン時の再送、ToDo、ドライブへの自動バックアップ（30日分の世代）、合言葉の再発行 |
| 引き継ぎ | 全データのバックアップ（アーカイブ・記録・設定を含む）、QR コード・連携コードでの移行、件数を確かめてからの復元、上書き前の控えと「元に戻す」、ファイルへの書き出し、データ形式の版数 |

### 入っていないもの

要件定義書 第2版でフェーズ3・公開時とされた機能は入っていません。
アプリ内再生（YouTube・ポッドキャスト）、人気番組テンプレート、YouTube のライブ配信予定の検知、
PC との同期、今日のまとめのメール送信、.ics 書き出し、メモのタグと画像、投げ銭です。

## 知っておいてほしい動作

- **1日は 5:00 に始まります。** 深夜の放送は、放送日の曜日を選んで 24:00〜28:59 で入力します（火曜 1:00 の番組は「月曜 25:00」）。
  第1版のデータで 0:00〜4:59 開始の毎週・隔週・単発の放送枠は、更新時に自動で深夜表記に直します（実際の放送日時は変わりません）。
- **放送枠は「放送日の曜日」で保存しています。** Google カレンダーへ送るときに実際の曜日（月曜 25:00 → 火曜 1:00）に変換します。
- **同期は差分方式です。** 端末のデータから Google 側のあるべき状態を計算し、前回送った内容と違うものだけ送ります。
  Google カレンダー側で直接編集した内容は、その予定が次に更新されるときに上書きされます。
- **アプリの同期とバックアップは、アプリを開いている間だけ動きます。** 新着の確認と今日のまとめは GAS が動かすので、アプリを閉じていても届きます。
  今日のまとめの材料（今夜の番組・締切・期限）は、アプリを開いたときに14日分を先に渡しています。
- **復元・ファイルの読み込み・共有ファイルでの上書きの前に、必ず控えを取ります。** 端末内に直近5件、ドライブにも残し、「元に戻す」で戻せます。
- **radiko の期限は目安です。** 無料は放送開始から7日、タイムフリー30 は30日で計算しています。
- **深夜の第5週・最終週の放送**（例：最終土曜 25:00）は繰り返しルールで表せないため、3年先までの日付を列挙して登録します。

### 実機で確かめていないこと

要件定義書 10.1 の Phase 0 の検証項目は、開発環境では確かめられないため、実機での確認が必要です。

- 睡眠・おやすみモード中に Google カレンダーアプリの通知が鳴るか（通知テストで確認できます）
- iPhone のホーム画面のアプリでカメラが使え、QR コードを読み取れるか（読めない場合は「連携コードを貼り付ける」）
- YouTube のチャンネルページから RSS を求める処理（YouTube のページの作りが変わると動かなくなることがあります）
- radiko のタイムフリーの放送回を開くリンク（`https://radiko.jp/#!/ts/局ID/日時`）。公式に公開された形式ではありません
- X の投稿画面・検索を開くリンク（形式は `js/links.js` にまとめてあります）

## 開発

```bash
python radio-calendar/tests/dev_server.py 8765
```

- `http://localhost:8765/tests/test.html` を開くとテストが走ります。`gas/Code.gs` は本物を読み込み、Google のサービスだけを偽物に差し替えて通しで確認します。
- 開発用サーバーはキャッシュを無効にしています。localhost では Service Worker を使いません（試すときは URL に `?sw` を付ける）。
- ファイルを変更したら `sw.js` の `VERSION` を上げてください（公開版で古いキャッシュが使われ続けます）。ファイルを追加したら `FILES` にも足します。
- QR コードの生成に qrcode-generator 1.4.4（MIT）、読み取りに jsQR 1.4.0（Apache-2.0）を `vendor/` に同梱しています。

```
js/time.js      日付と深夜表記の計算（Asia/Tokyo 固定）
js/rrule.js     放送枠の繰り返しと Google 用ルールへの変換
js/migrate.js   データ形式の版数と移行
js/store.js     IndexedDB とメモリ上のデータ、上書き前の控え
js/episodes.js  放送回・未聴・タイムフリー期限の計算
js/gcal.js      Google 側のあるべき状態の組み立て
js/digest.js    今日のまとめの材料
js/sync.js      差分同期、新着の受け取り、バックアップ、連携コード
js/mail.js      投稿メールと X の投稿、投稿履歴
js/share.js     番組の共有ファイル
js/stats.js     振り返りと採用率
js/links.js     X・radiko・YouTube のリンク形式
js/views/       各画面
gas/            Google Apps Script（中継役）
```
